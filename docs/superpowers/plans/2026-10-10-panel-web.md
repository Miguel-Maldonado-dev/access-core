# Panel web de control de acceso — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Objetivo:** reemplazar el administrador y el simulador de Tkinter por dos servicios Python para Raspberry Pi 3B y Orange Pi PC:
- un daemon que hace el control de acceso por UART;
- un panel web (FastAPI más una interfaz Next.js compilada a estática) con inicio de sesión del `.env`.

Ambos comparten una base SQLite.

**Arquitectura:**
- **Paquete `acceso`:** contiene el protocolo, el esquema, la migración, la autorización y los repositorios de datos.
- **Dos procesos:** `python -m acceso.daemon` (UART) y `python -m acceso.web` (Uvicorn) lo usan, cada uno como servicio systemd independiente.
- **Base:** SQLite en modo WAL con `busy_timeout`.
- **Interfaz:** se compila en la Mac con `output: 'export'` y FastAPI la sirve como archivos estáticos detrás de un middleware de sesión.

**Tecnología:**
- **Backend:** Python ≥3.9, FastAPI, Uvicorn (sin extras `[standard]`), pyserial, itsdangerous, python-dotenv, pytest y httpx.
- **Interfaz:** Next.js (App Router, TypeScript, Tailwind), Vitest y Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-10-panel-web-design.md`

**Skills útiles al implementar:**
- `frontend-design` y `vercel-react-best-practices` para las tareas 11 a 14;
- `sqlite-database-expert` para las tareas 3 y 4.

## Restricciones globales

- **Idioma y códigos:** toda la interfaz y los mensajes de error de la API están en español. Los códigos de tarjetas y RF se muestran y capturan **solo en decimal**, de 0 a 4294967295.
- **Python ≥3.9:** sin `match` y sin anotaciones `X | Y` en modelos pydantic; usar `Optional[...]` y `List[...]`.
- **Placa:** solo corre Python. Node.js se usa únicamente en la máquina de desarrollo, y Next.js usa `output: "export"` con `trailingSlash: true`.
- **Variables del `.env`:**

  | Variable | Por defecto |
  |---|---|
  | `UART_PORT` | obligatoria para el daemon |
  | `UART_BAUD` | `115200` |
  | `ADMIN_USER`, `ADMIN_PASSWORD`, `SESSION_SECRET` | obligatorias para la web |
  | `WEB_HOST` | `0.0.0.0` |
  | `WEB_PORT` | `8080` |
  | `DB_PATH` | `data/access_control.sqlite` (en la placa: `/var/lib/acceso/access_control.sqlite`) |
  | `LOG_MAX_ENTRIES` | `100000` |
  | `SESSION_HOURS` | `12` |
  | `CORS_ORIGINS` | vacía (solo para desarrollo) |
  | `STATIC_DIR` | `acceso/web/static` |

- **Archivo `.env` en la placa:** `/etc/acceso/acceso.env`, con modo `600` y dueño `acceso`.
- **Sesión:**
  - cookie `acceso_session` con `HttpOnly`, `SameSite=Strict` y `Max-Age = SESSION_HOURS*3600`;
  - comparación de la contraseña con `hmac.compare_digest`;
  - 1.0 s de espera por cada inicio de sesión fallido.
- **Protocolo v2.1:**
  - `0x10` (9 bytes), `0x11` (8 bytes) y `0x12` (5 bytes) llegan del ATmega;
  - `0x20` se envía con RelayID de 0 a 3 y duración uint16 MSB primero;
  - el checksum es el XOR desde CMD hasta el último byte del payload;
  - en `0x12`, el botón 0 corresponde a Relay1 y el 1 a Relay2, y **no se envía ningún comando**.
- **Códigos numéricos de los logs:** son los mismos que hoy, para que los logs migrados conserven su significado.
  - origen: 0 tarjeta, 1 RF, 2 botón de salida;
  - motivo: 0 Permitido, 1 Tarjeta desconocida, 2 Sin salida, 3 Sin permiso, 4 Error UART, 5 Control desconocido, 6 Botón sin salida, 7 Botón de salida.
- **Cantidades:** 4 salidas (0–3), 4 lectores (0–3), 4 botones por control (0–3) y permisos con id de 0 a 31.
- **Hora:** la zona horaria es `America/Mexico_City`. Los permisos se evalúan con la hora local del sistema.
- **UART:** el daemon reintenta abrir el puerto cada `RECONNECT_SECONDS = 3.0` segundos.
- **Programas actuales:** no se modifican los programas Tkinter ni la base `sqlite_access_control/access_control.sqlite` de la Mac. Las pruebas usan copias.
- **Ubicación:** todo el código nuevo vive en `panel_web/`, con su propio repositorio git.

## Riesgos a cubrir en las pruebas

Estas son las situaciones que el spec implica pero no prueba directamente. Cada una tiene su prueba en la tarea indicada.

1. **UART con basura, tramas cortadas o puerto que desaparece** (el ATmega se reinicia, un cable flojo): el daemon descarta lo inválido, procesa la siguiente trama válida y reintenta abrir el puerto cada 3 s sin terminar. Se prueba en las tareas 2 y 6.
2. **La web guarda mientras el daemon registra un evento:** ninguno de los dos falla con `database is locked`. Se prueba en la tarea 3.
3. **Filtro "hasta" de los logs:** incluye todo ese día en hora local (`America/Mexico_City`), incluido un evento a las 23:59:30. Se prueba en la tarea 10.
4. **Cookie alterada, vencida o ausente:** la API responde 401 y las páginas redirigen a `/login/`, nunca 500. Se prueba en la tarea 7.
5. **La migración corre dos veces, o por los dos servicios al mismo tiempo al arrancar:** hay una sola migración y un solo respaldo, sin errores. Se prueba en la tarea 4.

### Tarea 2: Protocolo UART

CREATE TABLE IF NOT EXISTS control_buttons (
